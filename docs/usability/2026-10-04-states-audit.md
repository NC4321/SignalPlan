# Empty, working and failed states: an audit — 2026-10-04

Done for [#159](https://github.com/NC4321/SignalPlan/issues/159), by reading the whole web app (`apps/web/src`: the panels, dialogs, canvas, 3D view, workers and persistence) with the main branch at D90. It's a read-through of the code and the text it shows, not a test with people, so it says what the app shows, not how it feels.

Every panel, dialog and view is listed in three states:

- **Empty:** nothing drawn, no access points, no survey, no neighbours.
- **Working:** coverage, the optimizer, calibration, locating, and the 3D view loading.
- **Failed:** a worker error, storage full or blocked, an unreadable file or scan, WebGL missing.

The rule from the issue: an empty state says what to do next, in a sentence, with the control to do it; a failure says what happened and what to try, and never leaves a blank area. In the tables, **Fine** means it already follows the rule. A gap carries the slice that fixes it: **A** (D91: failures in workers and storage, the error boundary, and this audit), **B** (D92: empty states in the panels) or **C** (D93: unreadable files and scans, and the 3D view). Gaps marked **A** are fixed in the same change as this document; B and C are fixed in theirs.

## Summary

The empty-state gaps share one cause: most panels are written for a plan that has something in it, and a hint is there only where someone thought of it. The failure gaps are mostly three kinds of thing that fail in the background without anyone looking: workers, storage, and a crash while drawing.

## What isn't covered

- **Errors outside rendering.** React error boundaries only catch errors thrown while rendering, in effects and in lifecycle methods. A throw in an event handler or a rejected promise is logged and the app carries on; each one found is listed above against a file.
- **Memory.** A plan too big for the engine to work on, or a tracing image too big to decode, shows up as a worker or image error and is handled as one, not separately.
- **Assistive technology.** The messages added use `role="alert"` where they block and `role="status"` where they inform; none of this was tried with a screen reader.
- **First-time users.** As with the earlier passes, this isn't the test in the [test script](test-script.md) ([#77](https://github.com/NC4321/SignalPlan/issues/77)).
